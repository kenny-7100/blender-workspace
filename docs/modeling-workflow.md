# 建模工作流

## 环境与入口

使用自带 Blender 4.5.9 LTS、内置 Python 3.11.11（macOS arm64）。`bin/blender` 与启动入口按自身位置定位根目录，并创建必要运行目录。迁移到其他系统仍需适配对应程序。图像工具使用 uv 隔离环境，不把系统 Python 和 Blender Python 混用。

```sh
./bin/blender --background --python-exit-code 1 --python projects/PROJECT/model.py
```

后台脚本用非零退出码报告异常，执行成功不代表模型质量通过。具体工具见 [参考建模工具](reference-modeling.md)。

## 私有项目与文件

每个模型放在 `projects/<项目名>/`，整个目录为个人数据并忽略：原素材、参考帧、项目脚本、参数、模型、贴图、预览、检查结果和项目 README 均不进入 Git。重要数据另行备份，不能把 `.blend1` 或本地保存当作远端备份。

持续项目 README 记录目标、主要工作文件、来源、工作方式、已确认决策、实际验证和下一步；个人素材细节保留在项目内，不复制进公共文档。只有泛化的通用方法和工具进入 `docs/`、`tools/`。

项目需要跨会话接续时，在 README 开头维护一个简短“当前工作入口”：当前采用的模型/预览、用户最近确认的约束、已验证到哪一步、首要未解决问题与下一步命令。已有正文链接复用，不复制整份报告；简单任务不强制模板。暂停、交接或有效阶段结束时更新，未变化不重写。恢复先看这个入口，不扫描全部素材或重读所有日志。

明确脚本主导、工作文件主导或混合方式。生成脚本可能覆盖同名输出，手工精修必须先另存；混合方式明确哪些集合允许重建。多个进程不能同时写同一个工作文件，需要并行时独立资产输出后统一组装。

## 验证与预览

本机性能有限，默认只提供本地静态图片，不自动打开 Blender GUI、创建网页或常驻预览服务。后台先小图低采样确认方向，必要时提高质量，串行渲染完成后退出。

按用途检查文件重新打开、关键对象、尺度和外部资源；外观改动查看图片，必要时多个角度对照。实体按需检查封闭性；游戏曲面、衣物、打印和绑定各有不同标准，不设无关的统一门禁。

原始素材保持不变；加工图片与时间、裁剪和色彩变换保持对应。纹理保留来源与许可，优先相对路径，交付时检查资源完整性或打包必要图片。相机未求解、尺寸未实测、颜色未标定时明确说明。

## Git 边界

Git 仅保存通用工具与不含个人数据的协作说明，禁止强制添加被忽略的个人数据。初始化时跟踪的项目示例已从索引移除并保留本地；此前推送版本仍在历史，不自动强推或改写。快捷 push 不插入额外扫描，应在普通任务产出时确保文件归位和隐私规则生效。
