# 建模工作流

## 当前环境与入口

当前工作区位于 `/Volumes/kenny/blender-workspace`，使用自带 Blender 4.5.9 LTS（macOS arm64）及内置 Python 3.11.11。`bin/blender` 和两个 `.command` 入口目前依赖固定绝对路径，迁移或硬盘更名后需要调整；尚未实现自动定位根目录。

从仓库根目录打开当前模型：

```sh
./bin/blender projects/robot-demo/robot.blend
```

重新生成机器人并渲染（会覆盖 `robot.blend`、`robot.png`、`verification.json`，必须先保护手工编辑）：

```sh
./bin/blender --background --python-exit-code 1 --python projects/robot-demo/model.py
```

`--python-exit-code 1` 使 Python 脚本异常可通过非零退出码报告。它不会自动检查模型质量；新文档中的这条命令尚未在本次初始化中重新运行。

## 项目与主要文件

- 每个模型使用独立 `projects/<项目名>/`，代码、确认保留的工作 `.blend`、参数和必要参考资源可纳入 Git。
- 持续编辑时在项目 README 标清主要工作文件与工作方式：脚本主导、`.blend` 主导或混合方式。没有明确要求时不迁移已有模型或批量重构。
- 脚本主导项目需要保留代码与参数；`.blend` 主导项目在工作文件副本上修改；混合项目应区分生成内容与手工内容，脚本只能重建明确管理的部分。
- 当前机器人只有单文件生成脚本，尚未实现集合级增量更新、参数文件、通用构建工具或多视图自动验收。场景朝向为前方 `-Y`、高度 `Z`，单位设置为公制；其他项目自行明确尺度和朝向，不机械沿用。
- 单次运行的批量图片、中间模型和报告放 `projects/<项目名>/outputs/<运行名>/`，由 `.gitignore` 忽略。当前机器人仍使用原来的固定输出路径，尚未自动迁移。

## 验证与交付

按改动选择必要检查：能否重新打开、关键对象与相机是否存在、尺寸是否符合需求、外部资源能否找到；外观变化需要查看实际图片，复杂形状增加正面、侧面、背面或透视图。用于打印、游戏或动画时再增加相应检查，不默认给所有模型施加同一拓扑标准。

优先快速预览，再按需要最终渲染；当前机器人脚本仍将建模、保存和渲染连在一起，尚未提供独立质量档位。未验证的 GPU、绑定或导出能力不得声明可用。

修改现有工作文件前保护已确认成果，避免覆盖唯一副本。多人或多个进程不得同时写同一个 `.blend`；需要并行时分别生成独立资产，再由一个集成步骤组装。

## Git 与资源保存

提交代码、文档、必要参数和经过选择的工作文件及预览；当前机器人 `.blend` 和 PNG 体积较小，初始化时保留。不要全局忽略所有 `.blend`，以免手工成果无法保存。

应用 `apps/`、安装包 `downloads/`、用户配置、资源下载目录、缓存、临时文件、日志、自动备份和批量输出均忽略。`scripts/` 中自维护的脚本仍可跟踪；下载的用户资源放在忽略目录，必要来源与版本另写入文档。不要靠 `git add .` 自动判断大文件价值；普通建模任务在产出时选择可维护的提交内容，快捷 push 不额外扫描。

纹理、字体及链接资产应保留来源、许可和可用路径，优先项目相对路径；需要打包交付时检查资源完整性。大文件增多后按实际需要选择 Git LFS 或外部版本备份，目前均未配置。忽略目录中的数据和 `.blend1` 不等于远端备份，重要成果需要另行备份。
