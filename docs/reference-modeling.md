# 参考建模通用工具

2026-11-14 建立的轻量本地工具。只有通用代码进入 Git；所有个人输入、项目脚本、模型、贴图、预览和项目记录都放在忽略的 `projects/`。默认只提供静态图片，不自动打开 GUI、网页或常驻服务。

## 视频与图像处理

`uv run` 按 `pyproject.toml`、`uv.lock` 在忽略的 `.venv/` 中准备 NumPy 和 Pillow。Blender 仍使用自身 Python；FFmpeg/ffprobe 使用本机现有程序。

```sh
uv run python tools/prepare_video.py INPUT_VIDEO --output projects/PROJECT/references/overview
# After selecting useful views, extract detail frames separately.
uv run python tools/prepare_video.py INPUT_VIDEO --output projects/PROJECT/references/frames --times 0.5,1.5,3.5 --height 1440
```

原件不变，输出时间命名 PNG、联系图和不含定位的清单。FFmpeg 应用显示旋转后缩放；采样时间对应邻近视频帧，不是精确姿态记录。拉普拉斯方差只是整幅图的清晰度辅助指标，不代表主体局部质量。

默认按视频实际时长均匀采样最多 12 帧，工作图高 480 像素，用于低成本总览；`--count` 调整总览数量。选定角度后再用 `--times` 和 `--height 1440` 提取细节。显式时间先全部验证，再写输出，避免处理到一半才发现越界；输出文件名的时间精度为 0.01 秒，重复名称拒绝。已有项目依赖特定帧名时保留显式时间，不用新的自动总览覆盖其参考来源。该工具尚无派生素材缓存或自动挑选主体功能。

HLG 使用近似反变换、BT.2020 到 BT.709 矩阵与固定 filmic 映射；不应用 Dolby Vision 动态元数据，不是颜色标定或去光照。其他 HDR 格式未配置专门变换。已用真实 HLG 竖屏素材验证解码与旋转抽帧，具体证据留在私有项目。

## 后台渲染与检查

```sh
./bin/blender --background FILE.blend --python-exit-code 1 --python tools/render_views.py -- --output projects/PROJECT/outputs/quick --quality preview --device METAL
./bin/blender --background FILE.blend --python-exit-code 1 --python tools/inspect_scene.py -- --output REPORT.json
```

渲染使用已有 `Camera.<名称>`，不保存场景改动，可选 `--device CPU`。Metal 在本机已实际完成渲染；无对应设备时明确失败，不静默切换。默认先小图低采样、串行处理，必要时提高质量，完成后退出进程。

工具默认只渲染 `Hero`，使用 `--quality preview`（24 samples、600 × 800）；明确需要最终图时用 `--quality final`（128 samples、900 × 1200）。显式 `--samples/--width/--height` 可覆盖档位，不为省时静默降低已要求的质量。设备默认仍为 CPU，本机已验证的 Metal 由调用者显式选择。

所有请求相机先统一检查，避免前几张渲染完才发现后面的名称无效。完成图通过临时文件替换，清单逐张记录耗时及 `running/complete/failed` 状态；只有当前清单中的完成视角能证明此次产出，目录中的旧图片不能代替。进程异常终止可能停留在 `running`，不能当作完成。记录便于比较相同输入和设置的耗时，不提供跨设备提速承诺，也尚未实现自动增量跳过。

检查读取 `role=asset` 网格，记录原网格和修改器求值后的非流形边、体积、尺寸以及缺失图片，不保存模型。实体项目可加 `--require-closed` 要求求值后封闭且正体积；有意开口的曲面不机械使用。不验证自相交、真实尺寸、照片相似度或材质准确性。

## 静态参考对照

```sh
uv run python tools/compare_reference.py --reference REFERENCE.png --render RENDER.png --reference-crop LEFT,TOP,RIGHT,BOTTOM --render-crop LEFT,TOP,RIGHT,BOTTOM --output COMPARISON.jpg
```

裁剪坐标按输入图片像素，输出并排比较图。工具不恢复相机、不校正透视，也不报告虚假的像素误差。结合近似参考相机判断轮廓与比例，不能把不同灯光的亮度差异全部归因于几何或材质。

项目特定的投射标注脚本留在私有项目。摄影测量、精确相机求解、自动分割、去光照与自动纹理拼接尚未实现，按真实需求选型。

## 首轮实践沉淀：问题、处理和边界

以下结论于 2026-11-14 根据一次实际建模、工具代码及渲染结果整理。仅保存通用方法，素材、标注、图像、日志和项目特定待办保留在私有项目 README。已实施的处理与尚待实现的建议分开记录，不把一次结果推广为所有物体通用标准。

### 多视角标签未对齐时，直接混合会重影

实际出现：人工估计相机角度、四边形校正后直接混合多视角投射，文字和图案出现双影。平面校正不能充分恢复圆柱透视、曲率与视角对应关系，权重混合也不能消除位置误差。

已采用的临时处理：完整正面图案优先使用一个来源，其他角度只补其不可用区域，避免在主要文字上平均混合；排除透过玻璃看到的纸背和背景。选帧既看局部清晰度，也看图案完整性，不能只选整幅图清晰度数值最高的一帧。

尚未解决：侧面接缝和局部比例仍是近似。后续优先补清晰近照或校准圆柱投影与特征对应，再处理接缝；不能靠放大贴图恢复原视频没有记录的小字。切换主要来源后，应复核它与原来参考角度的一致性。

### 样条平滑可能超出标注的半径

实际出现：轴心与外缘半径相差较大的截面使用 Catmull-Rom 插值后，局部半径超出控制点，尺寸与预期不一致。点数多或曲面看起来光滑不证明尺寸正确。

本次采用局部区间限幅控制半径和高度越界，并检查实际网格尺寸。限幅可能造成局部曲率变化，不是所有曲线的最佳方案；下一步有真实需要时选择保形插值或显式设计过渡。旋转体生成后先查最大半径、高度、壁厚与轮廓，再进入材质细化。

### 材质偏白或偏浅，不能只改基础颜色

实际出现：塑料颜色偏白、液体偏浅；调整灯光强度、反射参数和吸收后观感改善。灯光、色调映射、表面反射、背景和体积吸收共同影响画面，这次多个因素共同调整，没有证明单一根因。

诊断顺序：先核对源图色彩与曝光处理、场景尺度、相机和光照，再分别调整粗糙度/反射及吸收，每步保留同视角小图。玻璃还需查内外壁、法线、重叠介质和背后的环境；照片中透过玻璃的背景不能烘成玻璃颜色。吸收随路径长度变化，尺寸估计改变后需重看效果。

HLG 工作图和显示变换均不等于准确反射率；未进行受控颜色采集、去光照与同等光照复现时，不把颜色差异全部归咎于材质。

### 相机未对齐，会把透视差异误当作形状问题

当前对照仍使用近似相机与人工裁剪，不能证明比例或轮廓精确匹配。先明确焦距/裁剪、视角与至少一个实测尺寸，再调整外形；同一视角的误差尚未确认时，不连续细调模型迁就画面。

建议但尚未实现：对多个可见轮廓和关键点建立一致对应，用不参与主要调整的照片做交叉检查。并排图片是人工判断辅助，不是已标定的量化验收工具。

### 快速迭代应先减少无效工作，再考虑更重的工具

本次额外打开 GUI、搭建网页不符合用户的实际需要，已撤除；静态联系图和少量预览足够反馈。GPU 首次加载内核有额外耗时与内存占用，不能把冷启动全部计入每帧建模或渲染成本；已验证后复用结果，不每轮重新探测。

下次默认顺序：少量缩略帧检查覆盖 → 为选定视角提取足够清晰的参考 → 轮廓与相机粗对照 → 单视角低采样验证 → 细化标签与材质 → 必要的最终多视角。尺寸、隐藏部位与标签信息不足时优先补拍，而不是盲目增加面数或大图输出。

尚可优化但未实现：只重建发生变化的资产、只渲染受影响视角、缓存未变化的派生素材与模型构建记录。增量处理需要可靠的输入依赖与失效规则，不能仅凭文件存在就跳过。未测量端到端耗时，不承诺具体倍数提速。

代码检查另外发现全量读视频计算哈希会增加大文件内存占用；现改为流式计算。清单按实际源传递函数描述是否执行 HLG 映射，避免给未处理的其他格式错误标记。原先针对单个案例的默认时间表已替换为按时长采样；具体项目所需时间仍显式指定。

### 结构通过、图片打包和隐私保护分别检查

纸张原始网格可以是开口曲面，厚度修改器求值后才闭合；实体封闭性应查求值结果。正体积、无非流形边、无缺失贴图都不验证自相交、玻璃壁厚、照片相似度或制造可用性，不以结构报告替代视觉验收。

图片打包可减少丢失资源，但也可能将原参考帧或私人环境影像装进工作文件。忽略原视频不代表工作文件没有个人信息；整个项目仍按个人数据处理，另行备份，不进入 Git。项目专有经验保留本地，只有抽象后的方法与通用代码推送。

## 室内视频：先验证连通关系，再增加物件

室内行走视频中，反射、转身和被遮挡的门洞容易造成空间误判。先按时间记录可见区域与邻接关系，分别标注直接观察、镜中观察和估计尺寸；镜中出现的设备不能直接解释为另一组设备或另一个房间。以相邻数秒的连续帧复核门、家具和镜面的位置，再建立跨房间粗模。单帧无法确定的墙长与隐藏部位保留为假设。

阶段预览同时检查空间拓扑和几何冲突：门洞必须实际贯通，衣柜深度不能侵入床体，工作椅与通道需留出合理空间。先查看接近原视频的室内视角，鸟瞰剖视只辅助理解布局；没有标定相机和实测尺寸时，不把可通行、看起来相似写成准确复原。可用常见物件尺度初始化，但要在项目记录中写明它是估计。

持续迭代时保留每阶段 `.blend`、脚本快照、预览与本轮问题；当前入口指向最新有效成果和下一步。先交付粗模以便及时纠正，然后继续执行已授权的细化，不将阶段成果当作目标完成。个人空间与图像证据只留在私有项目，通用文档只保存方法。

### 在指定场景中渲染

`render_views.py --scene SCENE_NAME` 可选择已有场景，默认仍使用打开文件的当前场景。相机必须属于所选场景，渲染清单记录实际场景名；场景不存在时在渲染前报错。这适用于同一工作文件分别保存室内与无顶检查场景。工具不会自动移墙、剖切或保存场景改动；需要剖切时由项目脚本明确建立对应场景。

### 单平面拟合有多解，要保留独立证据

只用桌面或柜面对应点拟合相机，可能得到低残差但错误的空间解释；矩形旋转90度并改变相机位置，仍可能解释同一组三个桌角。用未参与拟合的门窗、厨房方向或邻接关系排除错误解，不能只按拟合数值选方案。明确标记手工像素点、假定物体尺寸、相机模型和越界约束；拟合结果碰到搜索边界时优先检查证据与假设。

柜门等近似矩形平面上的分缝，不应直接用照片像素高度或宽度比例建模：透视会改变这些比例。可先在较正面的清晰帧标注同一平面的四角，用逆单应变换将分缝点映射到单位矩形，再比较两端分缝的归一化高度与门组宽度。四角必须对应同一外边界，不能混用顶饰条、门板和地脚；保留原标注及矩形假设。它只提供该平面内的近似比例，绝对尺寸仍继承初始估计，也不能证明相机或整个空间正确。

新增室内机位渲染出全黑图时，先检查相机是否落在冰箱、柜体或墙等不透明实体内部，再诊断灯光和曝光。相机名存在、渲染进程成功都不能证明视角有效；修正位置后重新查看图片。对象包围盒只能辅助排查，对有孔洞、旋转或凹面的物体不能直接作为内部判定。

Blender后台可以通过临时`CLIP_EDITOR`上下文运行现有视频特征检测、跟踪和libmv求解。短片段实验中，删除短轨迹和高误差轨迹并选择有足够共视轨迹的关键帧后，局部残差可降低，但求解覆盖会缩短。保存实际成功的帧号、轨迹和相机，检查求解警告与重建有效范围，不把`FINISHED`或`is_valid`解释为整段成功；相机之间没有连通轨迹的时段不能自动接成完整户型。镜面、活动物体与手机处理可能影响跟踪，具体根因未经验证时不作定论。当前仍为项目内实验，没有通用自动摄影测量工具。

## 无界面上下文的基础网格

`tools/mesh_primitives.py` 提供基础网格函数：`box_mesh(name, dimensions)`、`uv_sphere_mesh(name, segments=24, rings=12)`、`cylinder_mesh(name, radius, depth, segments=32)`、`torus_mesh(name, major_radius, minor_radius, segments=40, sides=8)`。仅在Blender Python中调用，返回未关联对象的网格；调用方管理对象、集合、材质、变换和修改器。球为单位半径，其余按参数尺寸构建；圆柱和圆环沿Z轴。

用于程序生成较多基础物件时，避免每次调用`bpy.ops`和应用变换所需的上下文更新。尺寸须为有限正值，细分计数须达最小值，环管半径须小于主半径。已在Blender4.5.9后台验证四类网格封闭、法向正体积、与解析体积近似一致以及无效参数拒绝，并实际用于室内场景构建和渲染。体积近似容差取决于细分，工具不提供自相交、制造或视觉相似度认证；不承诺对所有场景同等提速。

对照图标题默认使用`VIDEO REFERENCE`与`BLENDER RENDER`，不会固定写某个项目版本。需要阶段标识时显式传`--render-label 'BLENDER vNNN'`，也可用`--reference-label`指定参考标题；版本文字仅是标签，不替代实际渲染清单。该选项已用现有参考/渲染生成并检查对照图。


### 薄板圆角不能只靠全边倒角

薄盖板或镜片使用全边倒角时，厚度可能限制可用倒角宽度，平面外轮廓仍显方。已增加`rounded_box_mesh(name, dimensions, radius, corner_segments=8)`：按XY平面圆角矩形轮廓挤出Z厚度，圆角半径独立于厚度。调用方旋转对象即可用于竖直镜片；它不额外倒圆上下边。半径不得大于较短平面边的一半，最大半径处去重相邻切点，避免零长边。已验证薄片、最大半径的圆形/胶囊边界、封闭性、正体积与解析近似，并实际用于渲染；不是通用任意轮廓圆角工具。

### 布料加厚后应检查接触面

程序生成被子或衣物时，下垂起点若位于支撑物内侧，会与下方床单等表面相交，产生交错露面的三角形。先核对下垂边界与实际支撑边缘，再检查Solidify等修改器求值后的顶点；沿法线加厚还会产生横向位移，原始表面高于支撑不代表加厚后无穿插。当前项目将下垂起点留在支撑外侧并验证支撑范围内的求值最低点，修复了可见问题。该高度检查只适用于已知平面支撑区域，不验证复杂折叠自相交；不要用增加细分或材质噪声掩盖穿插。

绕杆毛巾可用“前垂边—圆弧—较短后垂边”的连续截面建面，圆弧半径须给杆半径、布厚和余量留空间；褶皱幅度在贴杆处减小，向自由边增长。正面看不到的后垂边也可能与附近百叶或墙饰相交，已遇到这类求值网格三角相交；应检查具体邻近物并错开位置，不能仅检查原始顶点到杆轴的距离。顶点间隙与局部BVH表面检查仍不证明布料自相交或所有接触正确。

### 连续盆体避免拼块围边漏缝

独立方块围边配一块斜壁盆体，若使用了不同轮廓或倒角，斜视图可能露出黑缝。已用共享轮廓环连接台面、盆壁、盆底及底面，消除可见接缝；需同时检查边界边、非流形边、法向体积，并从斜上方和低视角查看。封闭网格只证明这些拓扑条件，不能替代盆深、外形、厚度与参考比例判断。
