# 文档维护与经验复用

目标是让下次协作减少重复提问、重复调查和重复踩坑。这里采用 GMX 与 Luna 项目的轻量方法，保留判断和知识入口，不引入 issue/PR 管理、分支回流或大型检查工具。

## 自动识别与保存

以下信号在任务过程中主动评估，无需用户另说“记住”：

| 信号 | 保存位置与方式 |
| --- | --- |
| 用户明确纠正或声明长期协作偏好 | 更新原规则；只有简短且跨任务高频的约定放 `AGENTS.md` |
| 经验证的故障根因与有效处理 | 更新对应专题：触发症状、原因、最短处理、成功标准、适用条件 |
| 影响后续工作的选择或约束 | 写入相关项目或专题：决定、理由、依据、重新考虑的条件 |
| 实质建模、调研或验证留下接续信息 | 更新项目 README：做了什么、结果文件、验证边界、未解决项与下一步 |
| 相同探索或操作重复出现 | 先改善已有方法；确有收益且步骤稳定时再提炼工具 |
| 旧说明失效、同一问题再次发生 | 修正原入口的可发现性、条件或过期步骤，不另写重复复盘 |

明确纠正和易丢失的重要决策及时写入；普通结果在自然切片、暂停、交接或交付前合并整理。简单任务可以只更新一两句，无增量则不新增文档。仅扫描列表、顺带阅读不要求逐项建档。

## 最小有效闭环

1. 需要既有经验时按导航、文件名或关键词定位，只读相关资料；上下文充分的快捷任务直接执行。
2. 写入前查已有主题，一个事实只在一处维护，其余位置链接引用。
3. 方法说明何时用、必要前提、最短步骤、如何判断成功和已知限制；事实附必要证据，易变信息附实际核验日期。
4. 下次遇到适用任务直接使用；环境或实现改变时只重验受影响内容。已由代码修复的问题撤掉不再必要的人工前置。

文档默认原地更新，历史由 Git 保存；不为每次语义更新新建时间版本或索引日志。新增或移动文档时更新导航与相关链接。文档改动检查路径、链接和规则一致性，不触发 Blender 渲染。

## 把经验带回执行

发现问题后选择最小有效落点，不给每次任务增加一套仪式：

| 经验类型 | 首选处理 | 下次如何生效 |
| --- | --- | --- |
| 明确且稳定的机械行为，如低成本预览、输入范围检查 | 修改现有工具默认值或校验，并做相关验证 | 正常调用就能得到正确行为，无需反复记住参数 |
| 需要判断的步骤，如透明物体选型、相机与材质诊断 | 更新对应专题的触发条件、最短步骤和限制 | 恢复或实施相关任务时按症状定位，不读取整套知识库 |
| 用户明确长期偏好 | 更新根规则并修正冲突入口 | 下一次默认遵从，不要求用户再次提醒 |
| 当前项目状态和待确认信息 | 更新私有项目 README 的当前工作入口 | 新会话直接接续，不重建已经确认的上下文 |

只在有证据且当前授权足够时落实工具修正；不把一次案例的时间点、物体参数或特殊命名做成通用默认值。依赖不足、收益未知或范围较大的方案标明尚未实现，不以持续改进为由顺带建设系统。

收尾时判断本次是否减少了下一次的具体工作：是否不再需要重复提问、重写命令、重新定位工作文件或规避同一错误。没有这种增量就不增加文档。再次遇到同样问题时，检查默认值是否仍错误、入口是否能找到、条件是否已失效；优先修正原位置。由工具自动解决后删掉过时的手动步骤。

性能优化依靠现有运行记录中的输入规模、设置和耗时判断，只记录本任务真正用到的数据；不建立评分或持续追踪系统。工具支持不代表原任务已经应用，私有项目中的旧结果保留其实际设置和日期，不因工具升级冒充重新验证。

## 内容与授权边界

- 区分用户确认、代码或运行验证、推测、计划。只读分析不能宣称实现完成，历史验证不能冒充当前结果。
- 一次性要求不自动成为长期偏好，一次环境成功不能推广为无条件步骤；未确认原因标记为待验证。
- 不记录凭据、完整会话、完整命令输出或无必要个人信息；运行日志与临时产物留在忽略目录。
- 收尾说明重要更新位置即可，不生成固定篇幅报告、评分、复用计数或自省任务。
- 沉淀在当前任务中实施，不代表实时监听或模型训练，也不扩大外部操作授权。
- 用户明确说 `push` 时完全遵循根 `AGENTS.md` 的快捷流程，不在其中插入本页的整理或检查；普通阶段收尾按本项目已授权的自动推送约定执行。
